v.1.3.1
   - Fixed: a source whose status already said "Connected" had the word printed twice when an agent asked for the current status, and a resource with no traffic had its name printed twice.
   - The readme described an Azure DevOps-only tool. It now covers Sentry and Application Insights, with setup for each, and the example MCP client configuration is valid JSON rather than a Windows path with unescaped backslashes.

v.1.3.0
   - New: Sentry monitoring. Huginn watches the projects you pick and raises crashes two ways. A crash that is new, has come back after being resolved, or has outgrown a mute is raised because it changed. A crash reaching at least five people and five per cent of everyone affected in the window is raised because it is big, however long it has been there. Each card carries a sparkline of the last twenty-four hours and a phrase for its shape, so a constant drip is told apart from a single burst at a glance.
   - New: Application Insights monitoring. Sign in with your own Azure account and pick the resources you can already see. Huginn reports routes that are failing, routes that are slow at the ninety-fifth percentile, failing dependencies, and resources that have gone silent, ordered by severity rather than by raw magnitude, so routes failing every call no longer sit below merely slow ones. Failing routes name the result code, because whether it is a 500 or a 405 decides what you do next.
   - New: connections are a first-class concept. Azure DevOps, Sentry and Application Insights each hold their own sign-in, their own list of what to watch, and their own status, and each keeps working while the others are broken. Every pane says when it was last checked, and a pane whose source cannot answer says so rather than looking calm.
   - The dashboard is built around what needs acting on now. Pull requests and builds share a column, since neither runs to many rows, leaving crashes and services a full column each. Card actions are icons with tooltips instead of words, which is what gives the titles room to be read.
   - Notifications are summarised per poll. A check that turns up ten new items used to fire ten separate toasts; it now fires one that names the count and what is in it. A single item still gets the detailed notification it always did.
   - New: Huginn can answer an AI coding agent asking what is currently broken. Settings has an Agents section that registers it with Claude Code in one press, and prints the command and configuration for any other MCP client. Reading needs no extra sign-in and opens no network port.
   - Settings written by a different version of Huginn are no longer discarded. Saving used to drop anything the running build did not recognise.
   - Settings are saved when you close the panel or the window, rather than only on an explicit save, so an edit interrupted by a restart is no longer thrown away.
   - Set HUGINN_PROFILE to give a build its own settings, credentials and state, so a second copy on the same machine shares nothing with the first.
   - Fixed: long pull request titles drew over the buttons beside them, and long build names were cut off mid-character instead of trimming.
   - Upgraded Avalonia to 12.1.2.

v.1.2.0
   - Bumped System.Drawing.Common from the transitive 4.7.0 to 9.0.0, clearing the GHSA-rxg9-xrhp-64gj critical-severity advisory that the release builds were flagging.
   - Rooted the Windows toast-notification dependency chain (Microsoft.Toolkit.Uwp.Notifications, Microsoft.Windows.SDK.NET, WinRT.Runtime) so the trimmer no longer strips reflection-only members on best-guess heuristics. The current call sites worked in practice, but any new toast template or WinRT activation path is now safe by construction rather than by luck.
   - Cleaned up the trim warnings the release builds had been logging: removed an unused Avalonia-template stub (DisableAvaloniaDataAnnotationValidation) Huginn never needed; the runtime platform dispatcher's [DynamicDependency] hints are now guarded so each TFM only references types that actually exist in it; the remaining safe-but-unprovable Type.GetType(string) calls in the dispatcher and the view locator carry explicit [UnconditionalSuppressMessage] justifications. The three IL2104 warnings from the rooted Windows toast/WinRT assemblies stay visible on purpose so a new noisy dependency wouldn't be silently swallowed.

v.1.1.0
   - New: Updates section in Settings shows the running version, lets you trigger a manual update check, and displays the release notes for the next version once it has been downloaded. A "Restart now" button appears alongside the notes so you can apply the update on demand instead of waiting for the next launch.
   - The toolbar "Update available" button now lives next to a much more discoverable Settings home for the same actions.

v.1.0.0
   - First stable release. Velopack auto-update is now wired end-to-end: the app polls GitHub Releases every 30 minutes, downloads new versions in the background, and applies them on next launch. The toolbar "Update available" button is a one-click install-and-restart that shuts Avalonia down gracefully so settings persist across the patch.
   - Retired the legacy update check that compared the embedded build timestamp against the ADO repo's latest commit — Velopack replaces it entirely.

v.0.1.0
   - First public release. Huginn moves from an internal ADO repo to a public GitHub repo at github.com/malforge/Huginn; the app itself continues to monitor Azure DevOps for pull requests and pipeline builds. Velopack-driven auto-update against GitHub Releases replaces the previous "open the repo to update" link.
